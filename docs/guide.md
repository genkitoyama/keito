## できること

- **機材・配線図**: 機材ライブラリから機材を置き、ポート同士をドラッグで結線。ケーブル種別（映像 / LAN / USB / 音声 / 電源 / DMX / シリアル / 同期 / RF / 光ファイバー / 無線）で色分けされ、ケーブルID（`HDMI-01` など）が自動で振られます。映像の規格（HDMI / SDI / DP など）と音声のコネクタ・用途（XLR / TRS / RCA / Phoenix / MIC / SPK など）はケーブルの品名・規格かポート名から読み取り、ケーブルIDの頭文字になります（`XLR-01` など。読み取れないときは `VID` / `AUD`）。長さ・ラベル・備考は右パネルで編集。
- **コメント（付箋）**: 付箋はコメントとして扱います。上のバーの「コメント」に未解決の件数が出て、押すと一覧が開きます（古い順、クリックでその付箋へ移動）。「✓ 解決」で解決済みにすると図では薄く表示され、一覧の「解決済み」にまとまります（まとめて消すこともできます）。PDF・画像の書き出しには、「付箋（コメント）も書き出す」を選んだときだけ入ります。未解決のコメントはチェック表にも出ます。シーケンス図の矢印やノートの上（または横）に置いた付箋は、その処理へのコメントになります。その行が黄色く示され、ソースを書き換えて行がずれても、図を動かしても付箋がついていきます。一覧と右パネルには「どの処理へのコメントか」が出ます。その処理をソースから消すと「対象の処理なし」と表示され、別の処理の上に置き直せば付け直せます。
- **フローチャート / 付箋 / エリア枠**: 図形の辺の●をドラッグで接続、何もない所に落とすと次の図形を作成。エリア枠に入れた機材は、機材リストの「設置場所」になります。
- **種別の選び方**: ケーブルは両端の端子に合わせて選び、中を流れるもので選びません。光 HDMI ケーブルは両端が HDMI なので「映像」、光エクステンダーの間は両端が光の端子なので「光ファイバー」、Dante の音声は LAN の端子どうしなので「LAN」です。「光」「12G-SDI」「Dante」のような中身や規格は品名・規格に書きます。ポートも同じく、その端子の種類で選びます。種別の一覧は「ケーブル（端子の種類）」「光・無線（中身は問わない）」「その他」に分けて並びます。
- **ケーブルの仕様・独自の種別**: ケーブルに品名・規格（「光 HDMI AOC」「Cat6A STP」など）、メーカー、型番、リンクを書けます。品名・規格は線のラベルに出て、ケーブルリストと集計にも入ります。HDBaseT のように専用の端子を持つ種別は、ボードごとに追加できます（色とケーブル ID の頭文字つき）。
- **ボード設定**: 何も選んでいないときの右パネルです。「基本情報」（タイトル・案件名・ボードの種類）と「線とラベル」（ラベルの文字サイズ、ラベルに出す項目、電源ケーブルの省略、跨ぎ線など、ボードのすべての線に効く設定）に分かれています。
- **ケーブル ID とラベル**: ケーブル ID（`USB-01` など）は右パネルで書き換えられ、ラベルに出す・出さないを線ごと、またはボード全体で選べます。ラベルの文字サイズは、ボード設定の「線とラベル」でボード全体を極小（8px）・小（9px）・標準（10.5px）・大（12px）から選べます（電源の両端表示も同じ割合で変わります）。線を選べば、その線だけ（複数選べばまとめて）ツールバーの文字サイズ（今のサイズが出ます）か右パネルで変えられます。一覧ではボード全体のサイズに「ボード全体と同じ」と付き、それを選ぶとその線はボード全体の設定に従う状態に戻ります。ボード設定で変えると、線ごとのサイズは解除されてボード全体の設定にそろいます。ラベルは改行できます（図の上では Shift+Enter、右パネルでは Enter）。
- **線の合流**: 同じポート（図形なら同じ辺）に入る線は、手前の 1 点で合流して 1 本になり、矢印も 1 つにまとまります。線を引いて既存の線の上に落とすと、その線と同じ行き先につながって合流します（入力ポートから引いた線は、その線の出どころにつながります）。合流した線は、落とした先の線と同じ色・矢印・線種になります。以前のボードの分岐点（小さな点）はそのまま表示・編集できます。
- **線を引くとき**: 図形の上下左右の点からドラッグすると、線はその辺から出ます。ドラッグ中は、離したらできる線が実際の経路で薄く表示され、行き先の図形（またはポート）や合流先の線が青く光ります。相手の図形の点に近づけるとその点が大きくなり、その辺に入ります。四角・付箋・テキストでは、辺の上ならどこで離してもその位置に入ります（離す位置に青い点が出ます。線の端をドラッグすれば後から位置を変えられます）。図形の中ほどで離すと、向きに合わせて自動で辺が決まります。線はなぞった形にもなります。引くときに角を付けてなぞる（例: 下へ → 横へ → 上へ）と、そのとおりに折れた線になり、まっすぐ引いたときはこれまでどおり自動の経路です（なぞった線は選んで「自動経路に」で自動に戻せます）。何もない所では作られる図形の位置が点線で出て、元の図形の上に戻して離すと取りやめになります。
- **交差の跨ぎ線**: ボード設定の「交差するところを跨ぎ線にする」をオンにすると、横の線が縦の線をまたぐ所に小さな山が付きます（既定はオフ）。
- **自動配線**: 向かい合うポート間の線は、折れ位置が重ならない・交差しない順に並び（エリア枠の間の通路を優先し、電源のタグも避けます）、機材を動かすとその場で並び直ります。線は機材や図形を避けて引かれます（単純な経路が何かを貫く場合だけ、周りを回る経路を探します。エリア枠とテキストは避けません）。
- **整頓**: 上のバーの「整頓」で、配置の骨格はそのままに図全体のバランスを整えます。エリア枠は中身のまわりの余白をそろえ（機材の上の IP・電源のタグや、ポート横の電源タグも枠の中に収めます）、縦に並ぶ枠どうしは左端・幅・間隔（60px）をそろえ、隣の列の枠と上端・下端が近ければ合わせます。枠の中では、同じ列の機材を同じ中心線にそろえ、列の間隔がほぼ同じなら均等にします。各機材は、いちばん近い「線が一直線になる高さ」へ上下に動かし（列の並び順は変えません）、合わせる線のない機材は、上の機材との距離を保ったままついていきます。手で折れ位置を決めた線は、そのまま残します（両端が一緒に動いたときは、折れ位置も一緒に動きます）。自動配線の線は、折れ位置が重ならないように並べ直します（線の位置は書き込みません）。動かすと何かに重なる場合と、線の交差・機材を貫く線・線どうしの重なりが増える場合は、その移動はしません。整頓で配線が前より込み入ることはありません。そのうえで、ほかの線と交差したり重なったりしている自動配線の線は、ほかの線をよけて通る道を探し、交差や重なりが減るならその道を折れ位置として書き込みます（いちどに直すのは、込み入っている順に 12 本までです。書き込んだ折れ位置は、線を選んで「経路を自動に戻す」で消せます）。枠の中の機材どうしの間隔は広がることはあっても詰めません。上端・下端がそろっていた枠は、そろえたままにします。線のつながっていない付箋・画像・シーケンス図などは、横に並んでいれば上端をそろえ、間隔がほぼ同じなら等間隔にします。最後に、線のラベルをそれぞれの線に沿ってずらし、ほかのラベル・機材・エリア名・ほかの線と重ならず、折れ目にかからない位置に置き直します（できるだけ線の中ほどに置きます。並んで走る線のラベルは、横向きの線なら縦一列に、縦向きの線なら横一列にそろえます）。何度押しても結果は同じです。⌘Z で戻せます。
- **凡例**: ツールバーの凡例ボタンで、このボードで使っている線の色の一覧（線の見本と名前）を置けます。同じ色の種別は 1 行にまとまり、右パネルで行の呼び名（「映像系統」など）と見出しを付けられます。線の色を変えたり線を足したりすると自動で追従します。右パネルの「機材の色（手配先）と会場の設備も並べる」をオンにすると（新しく置く凡例は最初からオン）、機材の色ごとの行と、会場の設備の網掛けの行も並びます。機材の行の呼び名は、名前を書かなければ色付きの四角の見本か機材の手配先から取ります。会場の設備に付けた色も、手配先の色と同じ意味（その会社が担当する設備）で読みます。凡例の幅を広げると、線と機材が左右 2 列に並びます。
- **線の色**: 線を選んで色を変えられます。ケーブルは種別ごと（このボードの映像ケーブルすべて、など）が既定で、「この線だけ」にも切り替え可。ポートの色と凡例も追従します。
- **線の調整**: ケーブル／コネクタを選択すると、縦・横どの区間にもつまみが出て、ドラッグで経路をずらせます（ポートから出る区間も、真っ直ぐな線も動かせます）。ラベルは線に沿ってドラッグで移動。機材をドラッグするときは、つながっているポート同士の高さがそろう位置に吸い付きます。両端の丸をドラッグすると別のポート・図形へつなぎ替え。「↺」で自動経路に戻ります。
- **電源（UPS・電源タップ）**: 電源ケーブルは線を省略し、両端に接続先だけ（`PWR-01 → メインPC` / `⚡ UPS`）を表示するので、多数の機器を UPS につないでも図が埋まりません。機材の本体にドロップすれば空きポートを自動で使い、足りなければ追加します。機材に消費電力(W)、UPS に給電容量(W)を入れると、UPS の上に「⚡ 5台 · 995 / 1200W」と負荷が出て、超過は赤で警告。「電源系統」表でも一覧できます。線で描きたいときはボード設定のチェック、またはケーブル選択時の「線を省略」で切り替え。
- **機材の色分け・見出し**: 機材ノードは色を付けて手配元や系統を区別できます（凡例は、凡例ボタンの凡例に機材の行を並べるか、色付きの四角を並べます）。エリア枠も色を変えられます。テキストは 標準／中見出し／大見出し／タイトル、図形と付箋の文字は 小／標準／大／特大、エリア枠のタイトルは 標準／大／特大／タイトル から選べ、いずれも太字を切り替えられます。
- **図形の見た目**: 8 色 × 塗り 4 種（淡い塗り / ベタ塗り / 白地に枠線 / 塗りなし＝透過）、枠の点線。コネクタ・ケーブルも点線にできます（種別が「無線」の線は、はじめから点線です。実線にもできます）。選択時に上に出るツールバーか右パネルで切り替え。
- **画像・SVG の埋め込み**: ツールバーの画像ボタン、キャンバスへのドラッグ＆ドロップ、クリップボードからの貼り付け（画像、または SVG のソースコード）で配置。SVG はベクターのまま、大きな写真は長辺 2400px に縮小して保存されます。角のドラッグで比率を保って拡縮（Shift で自由変形）。
- **履歴**: 編集が 2 分ほど止まったとき・別のボードに移るとき・CLI で書き換えるときに、その時点の図が自動で履歴に残ります（ボード設定の「履歴」。日ごとに並び、「機材 +2・ケーブル 3 本変更」のように何が変わったかが付きます）。提出した版など残したい時点には「名前を付けて残す」（★）で名前を付けると、消えずに残ります。名前のない履歴は直近 20 件と、それより前は 1 日 1 件（30 日まで）に自動で間引かれます。どの時点も開いて見る・その内容で書き出す・その時点に戻す（戻す前の状態も履歴に残る）ができ、「違い」でその時点から今までの機材・ケーブルの変更点を一覧にしてテキストでコピーできます（先方への「前回からの変更点」に）。
- **マイプリセット**: ボードに置いた機材を、右パネルの「マイプリセットに保存」で機材ライブラリに登録できます（名称・メーカー・型番・ポート構成・消費電力・色・リンクごと）。全ボード共通で、`boards/presets.json` に保存されます。
- **機材ライブラリ**: ふだんはよく使う機材（約 50 種）だけを並べ、一番下の「すべての機材を表示する」で全種類に切り替わります（検索は常に全種類から）。名前もポートも自分で決める機材は、上の「＋ 空の機材を置く」から置けます。カテゴリは最初たたまれていて、見出しをクリックすると開閉できます（「開く／しまう」で全カテゴリまとめて。開いたカテゴリは覚えています）。検索中はすべて開きます。
- **型番のリンク**: 機材に製品ページなどの URL を付けられます（右パネルの「型番のリンク」。型番欄に URL を貼り付けても入ります）。図では型番がリンク表示になり、選択時の「型番のページ」で開けます。機材リストと CSV には URL 列が付き、書き出した SVG / PDF でも型番がクリックできるリンクになります。
- **機材リスト・ケーブルリスト・ケーブル集計・電源系統・ネットワーク・チェック**: 図から自動生成。機材リストは名称・メーカー・型番が同じ機材を 1 行にまとめ、台数は名称の末尾の「x2」「×7」（または右パネルの「＋数量」で開く数量欄。1 つの枠で複数台を表すときだけ使います）で数えます。「区分」は機材の「手配先・担当」欄、空なら色分けの見本（「既存機材」「新規購入機材」のように、線につながず枠の外に置いた色付きの図形）から入ります。単価は機材リストの「単価(円)」欄に直接入力し（右パネルからは機材リストへのリンクだけ）、金額（単価×数量）と総額が出ます。右パネルの「会場の設備（持ち込まない）」に印を付けた機材（会場電源・備え付けのプロジェクターなど）は、図では点線の枠と縞模様の見出しで描かれ、左上に「会場」と出ます（機材の色を選べば、枠と縞がその色になります。選ばなければ灰色です）。機材リストには載らず、単価のチェックからも外れます。図・ケーブルリスト・電源系統・ネットワークには出るので、会場電源に回路の容量（15A なら 1500W）を入れておけば、その回路につないだ負荷の合計と超過を確かめられます。IP アドレス・ホスト名を入れた機材はネットワーク表に並びます。ケーブルリストは機材とポートを別の列に分け、どのエリアからどのエリアへ引くか（経路）も出します。電源系統は電源ごとの合計と容量に対する余裕・超過を出します（同じ名前の電源が複数あるときは「会場電源（展示室）」のようにエリア名を添えます）。チェックは IP の重複、容量超過、ケーブル ID の重複、種別の合わない接続、電源の未接続、長さや単価の未入力などをまとめて出します。
  - セルをクリックするとその場で編集でき、図に反映されます（まとめた行は、まとめられた全部に反映）。
  - 機材リスト・ケーブルリスト・ケーブル集計・ネットワークは、行の左端のつまみ（機材リストは No も）をドラッグして並べ替えられます。並びは表ごとに保存され、書き出しにも使われます。
  - 行クリックで図上の要素を選択、表計算ソフトへのコピーもできます。
- **YAML で読み書き**: ボード全体を YAML で取り出し・反映できます（git で差分管理可。`pos` を省略した要素は自動レイアウト）。画面ではなく、Claude Code やコマンドライン（下の「コマンドライン / Claude Code から使う」）から扱います。
- **エクスポート**: 書き出しはすべて右上の「エクスポート」にまとめています（PDF / 画像 / 表 / データの 4 タブ）。
  - **表（Excel / CSV）**: すべての表を 1 つの .xlsx に、表ごとのシートで書き出します。見出し固定・フィルター・プルダウン（区分・カテゴリ・種別・プロトコル・購入ステータス）付きで、金額や合計は数式です。購入ステータスの列は空で、Excel 側で管理する前提です。「前回の Excel を更新」で前に書き出したファイルを選ぶと、図の内容で書き直しつつ、購入ステータスや Excel で足した列（発注日など）を行ごとに引き継ぎます（新しい行は緑、変わったセルは黄色、図から消えた行は「削除された行」シートへ）。Excel で足したシートや、表の下に手で書き足した行もそのまま残ります。CSV は表を 1 つ選んで保存。
  - **データ**: 画像込みの keito ファイル（`.keito.json`、⌘S でも）と YAML。
  - **PDF** は A4 / A3 横で、1 ページ目に図、そのあとに選んだリスト（機材リスト・ケーブルリスト・ケーブル集計・電源系統・ネットワーク）が付きます。リストは本物の表なので文字を選択でき、長ければ自動で改ページされて見出し行が各ページに付きます。何も書かれていない列は出しません（印刷ダイアログ経由のベクター PDF）。何かを選択してから開くと「選択した要素だけ」を書き出せます（エリア枠を選ぶと中身も入り、両端が入っている線は分岐点ごと付きます。リストも選択範囲から作ります）。画像は PNG（1〜4x、透過可）/ SVG / クリップボードへコピー。
  - **案件まるごと**: 案件に 2 枚以上ボードがあると、上に「このボード / 案件まるごと」が出ます。案件まるごとにすると、PDF はボードごとに図とそのボードのリストを並べて 1 冊に（タブの順）、画像・Excel・keito ファイル・YAML はボードごとのファイルを 1 つの ZIP にします。

## 案件とボードの種類

ボードは案件（ボード設定の「案件名」）ごとにまとまります。同じ案件のボードは上部にタブで並び（システム図・ソフトウェア構成図・シーケンス図・自由ボードの順）、ワンクリックで行き来できます。タブの「＋」でその案件にボードを足せます。左上の案件名を押すと「ボード一覧」が開き、ほかの案件のボードも開けます。「＋新規」では種類を選んでボードを作れます。案件名の変更は、ボード一覧からその案件のボードすべてにまとめて反映できます。

| 種類 | 用途 | 道具・表 |
| --- | --- | --- |
| システム図 | 機材・配線・電源 | 機材ライブラリ、機材リスト・ケーブル表・電源系統・ネットワーク・チェック |
| ソフトウェア構成図 | アプリ・サーバー・サービスと、その間の通信 | 部品ライブラリ（TouchDesigner・API サーバー・DB・MQTT ブローカー …）、線の種別は HTTP(S)・WebSocket・OSC・MQTT・TCP・UDP・NDI など。線にポート（例: `7000/udp`）を入れると「OSC 7000/udp」とラベルに出て、通信一覧（送信元・送信先とそのホスト／IP・プロトコル・ポート）にまとまります。施設側へのファイアウォール申請にそのまま使えます |
| シーケンス図 | 起動手順や通信のやりとり | テキストで書くシーケンス図（雛形入りで始まります）。Mermaid（`sequenceDiagram`）や PlantUML（`@startuml`）の書き方をそのまま貼っても読めます（loop / alt / opt / par / group は該当する行を枠で囲み、左上に種類と条件、alt の else は枠の中の点線で分けます。autonumber、PlantUML の return、複数行のノートにも対応）。列が狭くて文字が折り返すときは、その行が自動で高くなり、矢印や隣の行と重なりません |
| 自由ボード | 打ち合わせのメモやラフ、配置図・画面割り・体験フローなどの絵 | 図形・付箋・テキスト・エリア枠・画像（平面図は「下敷きにする」で一番下に敷けます） |

種類はボード設定の「ボードの種類」から後で変えられます（描いたものはそのまま、使える道具や表が変わります）。

### ボードをまたいだ共有

同じ案件のボードどうしで、同じものをつなげられます。

- **同じもの**: 機材を選び、インスペクタの「ほかのボードとの共有」で相手を選ぶと、つながります（この欄は、同じ案件につなげられるほかのボードがあるときか、すでにつながっているときだけ出ます）。同じ名前のものがあれば「つなぐ」が出ます。名前・メーカー・型番・カテゴリ・IP・ホスト名・リンクがそろいます。どちらかで直すと、ほかのボードにもすぐ書き込まれ、開いたときにも新しいほうに合わせます。つないだものには図の右上に🔗が付き（書き出しには出ません）、「開く」で相手のボードのそれを選んだ状態で開けます。
- **動作ホスト**（ソフトウェア構成図）: 部品の「動作ホスト」でシステム図の機材を選ぶと、ホスト名と IP がその機材に合います。
- 同じ案件のほかのボードへ図をコピー＆ペーストすると、つながったまま貼られます（同じボード内の複製は別物になります）。
- YAML では `shared: キー`（機材）、`runsOn: キー`（部品）。`keito apply` で直した共有項目も、同じ案件のほかのボードに反映されます。YAML でキーだけ書いてつないだ場合は、システム図の機材の値にそろいます。

## コマンドライン / Claude Code から使う

keito のフォルダで `npm run keito -- <コマンド>` を使うと、画面を開かずにボードを読み書きできます（`npm run keito` だけで使い方が出ます）。

```bash
npm run keito -- boards                      # ボードの一覧（id・案件・種類・タイトル）
npm run keito -- new 体験アプリ構成 --kind software --project サンプル展示   # 種類と案件を指定して作る
npm run keito -- show サンプル > board.yaml   # YAML で取り出す（id・フォルダ名・タイトルの一部で指定）
npm run keito -- apply サンプル board.yaml    # 直した YAML を反映
npm run keito -- lists サンプル power         # 表を見る（equipment / cables / summary / power / network / comms / check）
npm run keito -- check サンプル               # チェック表（要修正があれば終了コード 1）
npm run keito -- xlsx サンプル --update 機材ケーブル表.xlsx   # 前回の Excel を更新（元のファイルは .bak.xlsx として残す）
npm run keito -- history サンプル             # 履歴（1 が最新）
npm run keito -- restore サンプル 3 / name サンプル 先方提出   # 履歴の時点に戻す / 今の状態に名前を付けて残す
```

- 書き込みはボードのフォルダに直接行うので、画面（開発サーバー）が止まっていても使えます。画面で開いているボードはすぐ読み直されます。
- 書き込む前に、元の状態を履歴に残します（画面の「履歴」にも「CLI で変更する前」として出ます）。
- `board.json` には書き込みごとに増える版番号が入っていて、読んだ後にほかで更新されていた場合は書き込みません。画面側も同じで、画面に未保存の変更があるときにほかから更新されると、上部に「ほかの場所で更新されました」と出て、読み込むか上書きするかを選べます（読み込んでも画面の変更は ⌘Z で戻せます）。
- ボードのフォルダは `--dir`、環境変数 `KEITO_BOARDS`、`~/.config/keito/config.json` の `"boards"` の順に探し、どれもなければ keito の `boards/` です。
- **Claude Code**: リポジトリに使い方（`.claude/skills/keito/SKILL.md`）を入れてあるので、keito のフォルダで「この系統図に PC をもう 1 台足して」のように頼めば、Claude Code が CLI で読み書きします。API キーは要りません。

## 操作

| 操作 | キー |
| --- | --- |
| 選択 / パン | `V` / `H`、Space+ドラッグ、スクロールで移動、⌘+スクロールでズーム |
| 図形 | `R` 四角 / `E` 端子 / `D` 判断 / `O` 楕円 / `C` 雲 / `S` 付箋（コメント） / `T` テキスト / `F` エリア枠 / `Q` シーケンス図（シーケンス図・自由ボード） |
| 機材ライブラリ | `L` |
| 置く場所を決める | ツールバーの図形やライブラリの項目を押すと、ポインタに枠が付いてくるので、置きたい所をクリック。図形とエリア枠はドラッグで大きさを決めて置けます。ボタンからボードへドラッグして離した所に置くこともできます。Esc でやめる |
| 範囲で選ぶ | 何もない所からドラッグ。囲みにかかった線も選ばれるので、そのまま Delete で消せます（線だけを囲めば線だけ） |
| 文字編集 | ダブルクリック / Enter / そのまま打ち始める。確定は ⌘Enter または Esc。入力に合わせて図形が伸びる |
| 次の図形 | 選択中の図形の辺の●をクリック、または ⌘+矢印。●をドラッグで既存の図形・ポートへ接続 |
| コネクタのラベル | コネクタをダブルクリック |
| 複製しながら移動 / 軸固定 | Alt+ドラッグ / Shift+ドラッグ（近くの図形の端・中心に吸着、⌘ で吸着オフ） |
| 空白をダブルクリック | その場に四角を作って入力開始 |
| 編集 | ⌘Z / ⇧⌘Z、⌘C / ⌘V / ⌘D、Delete、矢印キー（Shift で 1px） |
| 全体表示 / ファイル保存 | ⇧1 / ⌘S |
| ほかの案件へ | ⌘K（または左上の案件名）で、最近開いた案件が新しい順に並びます。数字キー 1〜9、または矢印と Enter で選ぶと、その案件で最後に開いていたボードが開きます。いちばん下の「すべての案件とボード…」でボード一覧 |
| 再読み込み（デスクトップアプリ） | ⌘R（メニューの「表示 > 再読み込み」）。保存していない変更を書き込んでから読み込み直します |

日本語入力: IME の変換確定 Enter では編集が終わりません。IME オンのままでもツールのショートカットが効き、図形を選択して打ち始めるとそのまま編集に入ります。

## 保存場所

`npm run dev`（または `npm run preview`）で動かしている間、ボードは PC 上のフォルダに自動保存されます。

```
boards/
  展示システム系統図__e6rbxg5k/     ← 「タイトル__ID」。タイトルを変えるとフォルダ名も追従
    board.json                      ← ボード本体
    assets/54c93f3f….png            ← 埋め込んだ画像（内容のハッシュ名。同じ画像は 1 つだけ）
    revisions/<ID>.json             ← 記録した版ごとの図
```

- ボードごとに URL があります: `http://localhost:5183/#/b/<ID>`。
- 画像はボードのフォルダにファイルとして置かれ、`board.json` には参照（`asset:…`）だけが入ります。容量の上限はありません。
- 削除したボードは `boards/.trash/` に移るだけです。ボード一覧の「最近削除したボード」から「戻す」で元に戻せます（同じボードがすでにあるときは戻しません）。ブラウザ保存（`?local`）のときも、直近 20 枚まではブラウザ内に残り、同じように戻せます。
- 保存先を変えるには環境変数 `KEITO_BOARDS=/path/to/dir npm run dev`（案件のリポジトリの中に置けば、図も git で管理できます）。`boards/` はこのリポジトリでは `.gitignore` 済み。
- 開発サーバー、コマンドライン、デスクトップアプリが同じフォルダに同時に書き込んでも、互いの変更を消さないように、書き込む間はフォルダの `.keito.lock` を取ります（数ミリ秒で外れます。異常終了で残ったものは 10 秒たつと引き継ぎます）。開発サーバーは動いている間、自分の URL を `.keito-server.json` に書きます（`keito url` が使います）。ボードのフォルダを git で管理するときは、この 2 つを `.gitignore` に入れてください。
- エクスポートの「データ」（または ⌘S）で、画像込みの単一ファイル（`.keito.json`）を作れます。人に渡すときはこちらか、ボードのフォルダごと。
- サーバー無しで開いた場合（静的ビルド）や URL に `?local` を付けた場合は、従来どおりブラウザの localStorage に保存します（約 5MB まで）。

## デスクトップアプリ

Tauri で包んだ macOS アプリとしても動きます（`npm run app` / `npm run app:build`）。中身はブラウザ版と同じで、違いは次のとおりです。

- ボードは PC のフォルダに保存されます。初回の起動時に、`書類/keito` を使うか別のフォルダを選ぶかを聞きます。あとからはメニューの「keito > 設定…」（⌘,）で変えられます。環境変数 `KEITO_BOARDS` か `~/.config/keito/config.json` の `boards`（コマンドラインと同じ設定）があれば、そちらが優先されます。コマンドラインや開発サーバーと同じフォルダを指せば、同じボードを読み書きします（片方で書き込むと、もう片方にすぐ反映されます）。

  ```json
  { "boards": "~/Documents/dev/keito/boards" }
  ```

- 書き出しは保存ダイアログで保存先を選びます。リンクは既定のブラウザで開きます。
- PDF は、印刷用のページを既定のブラウザで開き、そこで印刷（⌘P）して「PDF に保存」します（アプリの画面からは直接印刷できないため）。
- ウィンドウを閉じるときも ⌘Q で終了するときも、保存し終えてから終わります。保存できていない変更があれば確認します。
- ブラウザ版に保存していたボードは自動では移りません。ブラウザ版の「エクスポート → データ」で書き出し、アプリの「開く」で読み込みます。
